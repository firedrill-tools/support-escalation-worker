# Private support populations

Use support-escalation-cases list/init/inspect/reset. Initialization is exclusive and model-free. Reset requires a separate new root and preserves old source/evidence; it never rewinds an uncertain action.

| Profile | Cases | Source and observed task |
| --- | --- | --- |
| Starter | starter-due, starter-recent, starter-repeat | Original four tickets; unanswered, recent and an earlier human local queue. |
| Busy | busy-due, busy-repeat, busy-answered |48tickets,72events,16notifications,96human steps; four new due tickets, four earlier queues or four answered tickets. Eight uncertain prior remote reservations remain intact. |
| Ambiguous | ambiguous-reply, ambiguous-resolution, ambiguous-action-reply | A genuine separate human update during actual model/action HTTP invalidates an old read. A reported remote acknowledgement can coexist with current-source review_required. |
| Boundary | boundary-two-hours, boundary-calendar, boundary-revision | Exact two-hour eligibility, final calendar second and final safe revision. An exhausted later update refuses without losing the earlier queue. |

Pinned package assets preserve complete original fixture bytes and ordered human authoring history. scripts/build_populations.py recreates them through the actual Workspace seam. scripts/qualify_cases.py executes every case through the normal actual pinned SDKs and owned HTTP, verifies private data is absent from model requests, and checks every preserving reset after effects. Synthetic HTTP summaries are grounded in actual public request data; no fake model/client/SDK object is injected.

A queued local note is not delivery. Original remote ret.ok/channel/ts is a reported acknowledgement with actual delivery unknown. Incomplete duplicate state requires review; it is never automatically resumed or reposted. Prior human notes and observations grant no current model authority. Production account permissions, action semantics and actual Slack delivery require separately authorized live qualification.
